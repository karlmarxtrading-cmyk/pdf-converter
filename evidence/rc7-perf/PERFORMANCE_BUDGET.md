# Ketentuan pengukuran RC6 ↔ RC7

Angka pemicu ditetapkan sebelum menjalankan pasangan kandidat. Untuk setiap metrik, selidiki kenaikan median di atas 5% atau p95 di atas 10% kemudian ulangi pengukuran yang terdampak. Skenario yang berulang kali melewati batas tetap terbuka atau gagal. Catat variabilitas baseline, jumlah sampel dan output yang dibandingkan. Satu perbandingan yang kecil atau bising belum membuktikan penyebab regresi.

Kalibrasi terpisah pada RC6 menggunakan Node.js + jsdom, sebelum pengukuran kandidat. Untuk penyegaran dokumen kecil median 19,95 ms dan IQR 3,46 ms (12 sampel). Penyegaran 231 rumus memiliki median 830,15 ms dan IQR 49,80 ms (3 sampel). Ekspor HTML 231 rumus memiliki median 948,38 ms dan IQR 103,91 ms (3 sampel). Angka itu membantu mengenali noise pada perbandingan berikutnya. Pada distribusi berekor panjang dan n kecil, ulangi ambang yang terlewati. Median dan p95 dihitung per skenario, tanpa merata-ratakannya antar-skenario. p95 sampel berat berukuran 5 sama dengan nilai maksimum.

Perbandingan Node memakai 24 pasangan untuk kasus singkat dan 5 pasangan untuk kasus berat, dua pemanasan per kasus, urutan AB/BA bergantian, proses terpisah, titik GC identik, font dan CSS asli. Masukan panjang sintetis 116.126 byte mempunyai 24 bagian. Kasus 231 rumus berisi 15.280 byte. Kedua proses memakai BUS-01/A4. Validasi memeriksa sumber TeX, mode, jumlah rumus, CSS dan font di luar area pengukuran. Pengukuran HTML dan payload cetak dimulai setelah badan dokumen siap. Durasi parsing/KaTeX dalam Node berada dalam satu fase `parseAndRenderMs`. Pengukuran penggunaan memori memisahkan heap mentah sebelum dan sesudah GC. RSS mencakup keseluruhan proses.

Pengukuran Chromium memakai dua tampilan produksi dengan sumber sama di server lokal, tanpa kait QA. Satu iframe aplikasi baru untuk setiap giliran, cache HTTP browser hangat setelah satu pemanasan. Lebar 1366 × tinggi 900, BUS-01/A4. Aktivitas editor dihasilkan dengan event input sintetis. Latensi terukur mencakup debounce, worker, penyusunan iframe dan kesiapan font. Paginasi memakai jalur tab Halaman, jika entri cetaknya cocok. Uji pengaturan clipboard dan penyimpanan berkas secara native dilaporkan terpisah. Pada uji waktu ekspor, harness menangkap Blob dari tautan unduh aplikasi, mencegah penyimpanan file berulang, lalu memeriksa CSS/font/rumus di luar pengukuran. Ini mengukur waktu sampai aplikasi melaporkan siap unduh.

Percobaan browser lokal memakai HeadlessChrome/153.0.8010.0, dua origin terisolasi dan dua pohon build asli. Kalibrasi RC6 selesai sebelum pasangan kandidat. Enam sampel startup RC6 memberi median 132,55 ms (rentang 129,7–176,0 ms). Dua sampel paginasi awal 231 rumus, 3.448–3.776 ms. Ambang penyelidikan tetap 5% untuk median dan 10% untuk p95. Perbandingan headless tidak mencampur sampel cloud Chromium 156. Dataset memori berisi 3 pasangan dan 8 pembaruan per proyek, dibaca melalui CDP setelah GC pada revisi ke-1, ke-4, ke-8 di target yang sama.
